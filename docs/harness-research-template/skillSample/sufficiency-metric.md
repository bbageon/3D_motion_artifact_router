# Sufficiency Metric Skill — Research Track Template

본 skill은 [`02-sensor.md §1-5`](../02-sensor.md)의 "시험 충분성" 감지 대상과 [`03-test.md §6`](../03-test.md)의 충분성 운영 원칙을 본 트랙(line coverage가 적용되지 않는 ML/통계 파이프라인)에 맞게 구현한다. 본 skill은 일반 SW 트랙의 [`../harness-template/skillSample/coverage-sufficiency.md`](../../harness-template/skillSample/coverage-sufficiency.md) 위치를 도메인 충분성 지표로 대체한다.

본 skill은 [`01-instructions.md §2`](../01-instructions.md)의 문장 형식 규칙을 그대로 따른다.

---

## 1. 목적

본 skill은 다음을 보장한다.

- 도메인 충분성 지표의 임계값이 트랙·체크포인트·split 전체에서 일관되게 해석된다.
- 임계값 미달 시 Agent가 동일한 원인 분류 + 복구 절차를 수행한다.
- 임계값 변경 이력이 추적 가능한 형태로 남는다.

### 1-1. 본 skill이 맡지 않는 것

- 게이트 배치 결정 — 02-sensor.md §3.
- 게이트 실패의 판정 의미 부여 — 02-sensor.md §4.
- 모델 학습 파라미터 조정 — AGENTS.md §4.

본 skill은 위 문서의 구조를 입력으로 받아 **도메인 충분성 지표의 임계값 적용·복구만** 판정한다.

---

## 2. 임계값 정의 (도메인이 선택)

본 트랙의 충분성 지표는 도메인이 선택한다. 흔한 후보는 다음과 같다.

- **parse success rate** — 모델 출력이 도메인 파서를 구조 오류 없이 통과한 비율. NLP·구조화 출력 도메인.
- **domain pass rate** — 도메인 의미 검증을 통과한 비율(예: motion prediction에서 뼈 길이가 사전 정의 범위 내).
- **prediction interval coverage** — 예측 구간이 ground-truth를 포함한 비율. 회귀·시계열.
- **calibration error** — 예측 확률과 실제 빈도의 차이(ECE 등). 분류·확률 출력.
- **constraint satisfaction rate** — 도메인 제약 조건을 만족한 출력 비율(예: 분자 생성에서 valence 규칙).

적용본은 본 절을 도메인 지표 정의로 채운다.

### 2-1. 임계값 초기값 (적용본이 결정)

본 임계값은 **초기값**이며, snapshot ≥ 20개 누적 시 §5 절차로 보정한다.

- **smoke 임계값** — quick smoke 추론에서 충분성 지표가 0%이면 hard fail. 0%는 토큰 포맷·파서·토크나이저 회귀의 강한 신호.
- **검증 split 기본 임계값** — 검증 split 전체에서 충분성 지표 `≥ <적용본 정의값>` (트랙별 분리 적용).
- **검증 split 격상 조건** — 직전 스냅샷 대비 충분성 지표가 `<적용본 정의값>p` 이상 하락하면 soft fail.
- **트랙 비대칭 격상 조건** — 한 트랙의 충분성 지표가 다른 트랙보다 `<적용본 정의값>p` 이상 낮으면 soft fail.

### 2-2. 임계값 적용 게이트

- 빠른 국소 게이트 → smoke 임계값(0% 금지) 확인.
- 전체 게이트 → 검증 split 기본 임계값과 격상 조건 함께 확인.
- 강한 기준(mutation 류)은 본 트랙에 적용 불가 — ML 모델에 정의가 모호하다.

### 2-3. 금지 규칙

- 임계값을 하향 조정하지 마라. 회귀 해소를 위해 기준을 낮추는 것을 금지 — AGENTS.md §6.
- 모델 출력을 후처리(정규식 보정 등)로 충분성 지표를 인위적으로 끌어올리지 마라. 본 지표는 **모델이 도메인 계약을 따르는 정도**를 측정한다. 후처리는 측정 의미를 왜곡한다.
- "100% pass rate" 같은 수치 목표를 잡지 마라. 100%는 모델 품질을 보장하지 않으며, 출력을 단순화시키는 학습 왜곡을 유발할 수 있다.

---

## 3. 판정 절차

1. quick smoke 추론을 실행하고 충분성 지표 산출.
2. 0%이면 → 즉시 hard fail. §4 원인 분류로 진입.
3. 0%가 아니면 → 트랙 평가기로 검증 split 평가 수행.
4. 트랙별 충분성 지표를 §2 임계값과 비교.
5. 직전 스냅샷과의 차이를 §2 격상 조건과 비교.
6. 미달 또는 격상 조건 충족이 있으면 → §4 복구 절차 실행.
7. 통과하면 → 다음 게이트로 진행.

### 3-1. 판정 출력 형식

- 실패 시 출력은 "어떤 트랙이, 어떤 체크포인트에서, 어떤 split의 어떤 지표가, 어떤 임계값을, 얼마나 미달했는지"를 포함.
- Agent가 파싱 가능한 구조(JSON)로 출력.

**IMPORTANT:** 판정이 hard fail로 격상된 상태(smoke 0% 또는 §2 격상 조건 충족)에서는 커밋하지 마라.

---

## 4. 복구 절차

### 4-1. 원인 분류 4범주 (도메인이 보정)

본 4범주는 generic baseline이며, 적용본은 도메인 의존 카테고리로 보강한다.

- **포맷·인터페이스 회귀** — 인코더·파서가 비대칭으로 변경됨. change-obligation 매핑 점검·round-trip 검증.
- **토크나이저·feature extractor 회귀** — 외부 자산이 변환기·학습기·추론기 중 한 곳에서 다르게 로드됨. vocab/feature id 일치 확인.
- **모델 학습 회귀** — 학습 분포가 도메인 계약을 더 이상 따르지 않음. 학습 데이터의 입력·출력 일관성 점검.
- **시퀀스/입력 길이 한계** — 모델 출력이 최대 길이를 초과해 잘림. `max_new_tokens` 또는 도메인 동등 설정과 학습 시 `max_length` 비교.

### 4-2. 복구 단계

1. §4-1의 범주 중 어디에 해당하는지 분류.
2. 포맷·인터페이스 회귀이면 → change-obligation 복구 절차로 위임.
3. 토크나이저·feature 회귀이면 → 변환기·학습기·추론기의 외부 자산 경로 인자 확인 + 재생성.
4. 모델 학습 회귀이면 → 학습 데이터를 일부 샘플링해 prompt/completion 또는 입력/출력 일관성 확인. 회귀 확인 시 데이터 재생성 또는 학습 재개 검토.
5. 시퀀스/입력 길이 한계이면 → 길이 설정을 조정하거나 윈도·feature 수를 줄임.
6. 본 skill 판정 재실행해 임계값 회복 확인.

### 4-3. 보완이 어려운 경우

- 4범주 어디에도 해당하지 않으면 → 회귀 리포트에 미분류 사례로 등재. eval-compare 피드백 루프로 넘김. 미분류 사례가 누적되면 §4-1을 갱신.
- 모델 학습 회귀가 확정되었지만 재학습 비용이 즉시 감당 안 되면 → 직전 체크포인트로 롤백. 평가 결과는 직전 체크포인트 기준으로 기록.

### 4-4. 금지 규칙

- 모델 출력을 후처리해 충분성 지표를 끌어올리지 마라(§2-3).
- 미달을 발견했음에도 "다음 PR에서 처리"로 미루지 마라.
- 의미 없는 출력으로 형식만 충족시키지 마라. 충분성은 행동의 강도를 측정하는 것.

## 5. 임계값 변경 절차

§2의 임계값을 변경할 때:

1. 상향 조정만 허용. 하향은 금지(§2-3).
2. 변경 근거를 커밋 메시지에 인용. 근거는 다음 중 하나.
   - `evals/snapshots/{daily,weekly}/*.json` 누적 ≥ 20개의 MAD(중앙값 절대편차) 또는 표준편차 기반 보정. 근거 문헌은 [`04-evaluation.md §3-1`](../04-evaluation.md).
   - 회귀 리포트에 기록된 반복 미달 카테고리.
   - 핵심 경로 정의의 변경.
3. 본 skill 본문(§2)과 [`03-test.md §6`](../03-test.md)·[`02-sensor.md §1-5`](../02-sensor.md)의 서술을 동시 갱신.

## 6. 유지보수 규칙

- 임계값(§2)을 변경했으면 → 변경 근거(스냅샷 또는 회귀 리포트 경로)를 함께 기록.
- 본 skill의 판정 결과가 **지속적으로 같은 트랙·체크포인트의 미달**을 감지하면 → 핵심 경로 정의와 학습 파이프라인의 적정성을 재검토.
- 4범주 분류(§4-1)에 매번 들지 않는 미달 패턴이 누적되면 → §4-1을 확장.
- 본 문서 용어가 02-sensor.md·03-test.md·기타 skill과 불일치하면 → `02`를 지도, `03`을 방법론의 원본으로 간주하고 본 문서를 갱신.

<IMPORTANT>
충분성 지표는 "수치를 충족했는가"가 아니라 **"모델이 약속된 도메인 계약을 따르는가"** 를 묻는다. 후처리·정규화·기준 완화로 수치만 충족시키면 02-sensor.md §1-5의 시험 충분성 감지 대상이 의미를 잃는다.
</IMPORTANT>
