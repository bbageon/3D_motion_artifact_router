### 2-2. Circular calibration 문제

**용어** — **circular calibration**: calibration source (quality proxy) 가 calibration target (NetGain weight) 의 한 항을 직접 포함할 때, 그 weight 를 키우면 NetGain 이 quality proxy 의 affine transform 으로 trivial 수렴.

본 calibration 에서:
- quality proxy `Q = -FidelityLoss_protocolA`.
- `NetGain = ArtifactReduction - α·FidelityLoss - β·CorrectionMagnitude - γ·ToolCallCost`.
- α → ∞ 일 때 `NetGain ≈ -α·FidelityLoss = α·Q` (positive affine of Q) → Spearman(NetGain, Q) → 1.0.

따라서 grid search 가 더 큰 α 에서 더 높은 ρ 를 항상 출력하는 것은 **수학적으로 trivial**. v1 의 α=5.0 → v2 의 α=50.0 → (만약 더 확장하면) α=500.0 도 더 높은 ρ 를 줄 것이지만, 어느 것도 routing 의 본질 (artifact reduction vs fidelity preservation 의 trade-off) 을 잡지 못함.

**근본 해결**: quality proxy 를 FidelityLoss 와 독립적으로 정의해야 함.
- 후보 1 — perceptual rating (MOS): 비용 ↑, 본 단계에서 미적용.
- 후보 2 — composite quality (artifact reduction × fidelity preservation 의 multiplicative): NetGain 본 형태와 다른 함수.
- 후보 3 — distributional quality (FID_motion, FGD on real-motion distribution): batch-level metric 이라 per-candidate ranking 부적합.

본 일지는 **문제의 인식** 만 보존. 해결은 후속 작업.

### 2-3. α-sensitivity per-sample gap

[`evals/snapshots/per_sample_gap_alpha_sensitivity_v1.json`](../evals/snapshots/per_sample_gap_alpha_sensitivity_v1.json) (90 keys = 30 samples × 3 artifacts)

| α | bone (strict/tie/loss) | foot (strict/tie/loss) | jitter (strict/tie/loss) |
|---|---|---|---|
| **1.0** | 4 / 26 / 0 | 19 / 9 / **5** (?!) | 30 / 0 / 0 |
| **5.0** | 4 / 26 / 0 | **22 / 8 / 0** ← v1 ref | 30 / 0 / 0 |
| **10.0** | 4 / 26 / 0 | 20 / 8 / 2 | 30 / 0 / 0 |
| **20.0** | 4 / 26 / 0 | 19 / 11 / 3 | 30 / 0 / 0 |
| **50.0** | 4 / 26 / 0 | 19 / 10 / 4 | 30 / 0 / 0 |

**핵심 발견**:
1. **α=5 (v1 reference) 에서만 mathematical guarantee (gap ≥ 0) 가 정확히 성립** (foot_loss=0).
2. **α ≠ 5 에서 foot_floating 에 n_loss > 0 발생**. 이는 mathematical violation 이 아니라 **truncation artifact**:
   - sequence raw 는 v1 NetGain weight 기준 **top_k_candidates** (top-3) 만 저장.
   - α 가 v1 과 다르면 true best 가 top_k 밖일 수 있음 → 측정된 sequence best 가 진짜 best 보다 낮을 수 있음 → 측정된 single_step best 가 더 높아 보이는 false-loss 발생.
3. **bone_stretch / global_jitter 는 모든 α 에서 robust**. foot_floating 만 top_k truncation 에 민감.
4. **Strict advantage 비율의 magnitude 는 α 따라 변동**. 예: jitter median gap (α=5) +0.0058 → (α=50) +0.058 (10x), foot median gap (α=5) +0.0028 → (α=50) +0.0042. magnitude 차이는 fidelity_loss scale 비례.

### 2-4. 결정 사항

1. **v1 α=5.0 calibration 유지**. status tag = `calibrated_protocol_a_v1` (변경 없음).
2. **v2 grid 결과는 sensitivity 산출물로만 보존**. v2 calibration constant promote 하지 않음.
3. **AGENTS.md §6-11 의 'provisional NetGain weight tagless 인용 금지' 가드 강화 필요** — 추가로 `calibrated_protocol_a_v1` 도 calibration source 의 circularity 를 인지하지 못한 채 인용하면 안 됨. 후속 task.
4. **H-2026-204 RQ2 의 결론 보존 가능**:
   - α=5 에서 73-100% strict advantage 의 결론은 그대로 유효.
   - α 의 다른 값에서 magnitude 가 변하지만 ordering (sequence ≥ single_step) 은 모든 α 에서 mathematical 으로 유지.
   - 단 magnitude-based 결론은 calibration 종속이므로 paired test 의 effect size 보고 시 α 명시 필수.

## 5. 실패한 시도 (negative results)

### 5-1. α-sensitivity 측정 시 foot_floating false-loss

설명: sequence raw 의 top_k 가 v1 weight 기준이라 α 변경 시 측정된 sequence best 가 incomplete 인 한계. AGENTS.md §3-13 (negative result 보존) 에 따라 본 한계를 명시.

복구: 완전한 α-sensitivity 가 필요하면 sequence oracle 을 v2 weight (α=50) 로 re-run 하여 새로운 top_k 를 logging. 본 단계에서는 보류 (computational cost vs research value).

### 5-2. v2 calibration promote 시도 보류

`CALIBRATED_PROTOCOL_A_NETGAIN_WEIGHTS_V2 = {alpha=50.0, beta=1.0, gamma=0.0}` constant 를 `orchestrator/oracle_single_step.py` 에 추가하려 했으나 §2-2 circular calibration 발견으로 보류. v2 promote 는 quality proxy 가 FidelityLoss 와 독립적으로 정의된 후로 미룸.
