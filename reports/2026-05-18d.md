### Rule-based orchestrator 동작

알고리즘 (`orchestrator/rule_based.py` `RuleBasedOrchestrator.decide`):

1. evaluator_reports 가 비어있으면 → STOP, `stop_reason="no_evaluator_reports"`.
2. 모든 severity 가 `stop_severity_threshold` (default `"low"`) 미만이면 → STOP, `stop_reason="all_severities_below_threshold"`.
3. actionable report 들 중 severity desc → score desc 순 정렬해 primary 선정.
4. primary 의 `recommendation` field 를 tool 이름으로 매핑 (`DEFAULT_TOOL_LOOKUP`). 매핑 안 됨이면 → `reject`, `reject_reason="no_tool_for_recommendation_..."`.
5. revise decision metadata 에 **모든 evaluator report 의 before snapshot** 박제 (Guard 5 의 'before' 절반).

매핑 default:

| recommendation | CorrectionTool |
|---|---|
| `foot_lock_tool` | `FootLockTool` |
| `bone_projection_tool` | `BoneProjectionTool` |
| `velocity_smoothing_tool` | `VelocitySmoothingTool` |

severity → strength 단순 매핑: `low → small`, `medium → medium`, `high → large`.

### Tool effect matrix (`compute_tool_effect_matrix`)

각 `(artifact_kind × tool × strength)` 조합에 대해:

1. corrupted motion 으로 시작 (= synthetic injection 또는 generator output).
2. tool 적용 → corrected motion.
3. corrupted, corrected 양쪽에서 **모든 evaluator** 의 score 측정.
4. target evaluator 의 `target_delta` + 다른 evaluator 의 `cross_evaluator_delta` 모두 기록.

`ToolEffectEntry` schema:

```
- artifact_kind: str
- tool_name: str
- strength: str
- target_evaluator: str
- target_score_before / target_score_after / target_delta: float
- correction_magnitude: float
- cross_evaluator_scores_before / _after: dict[evaluator_name, list[report_dict]]
- cross_evaluator_delta: dict[evaluator_name, float]  # AGENTS.md §6-12 의무
- metadata: dict
```

잘못된 target_part 입력 (예: `BoneProjectionTool` 에 `"both_feet"`) 은 ValueError → `metadata.skipped=True` 로 기록 (silent 실패 회피).

## 실패한 시도 (Negative Results)

- **`test_tool_effect_matrix_foot_lock_reduces_floating` 의 fixture 설계 결함**:
  - 시도: `_make_standing_motion` 을 foot 만 y=0 으로, 나머지 joint 를 y=1 로 두고 `inject_foot_floating(lift_height=0.20)` 으로 corrupted motion 생성.
  - 실패 양상: target_score_before = 0 — FootFloatingEvaluator (v1.2.0) 가 floating detection 안 함.
  - 원인: auto ground 추정 (motion.min y) 이 lift 와 동기 — foot 만 다른 joint 보다 아래에 있다가 lift 되면 motion.min 이 그만큼 올라가 height_above_ground = 0.
  - 폐기 사유: 본 evaluator 의 ground 추정은 design 대로 동작. test fixture 의 설계 결함이지 evaluator 버그가 아니다.
  - 해결: fixture 에 PELVIS 를 ground anchor (y=0) 로 박아 lift 와 무관하게 motion.min 이 0 유지. lift_height 도 (tau_float 0.05, tau_contact_height 0.10) 사이의 0.08 로 조정.
  - 교훈: synthetic fixture 가 자동 ground 추정 등 evaluator 의 heuristic 와 어떻게 interact 하는지 명시. 본격 평가의 corrupted motion 은 HumanML3D GT 의 anatomical 구조 (다중 ground 후보 joint) 를 갖고 있어 실 case 에서는 본 함정이 안 일어남.
