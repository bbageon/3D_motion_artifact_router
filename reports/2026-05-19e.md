## 2. 파악한 부분 — 핵심 발견

### 2-1. 공식 demo.py 와 wrapper 의 batch['length'] 차이

| Source | line | batch['length'] |
|---|---|---|
| 공식 demo.py | `load_example_input` line 39 → batch line 181 | `motion_lengths` = `[0] * len(Lines)` (plain text prompt 의 경우) |
| wrapper | [`_motiongpt_inference.py`](../generators/_motiongpt_inference.py) | `[args.n_frames]` (default 40, smoke 시 60 시도) |

→ wrapper 가 공식 path 와 다른 호출. **length issue 의 직접 원인일 가능성 큼**.

단 본 가설 검증은 length=0 patch 시도가 hang 으로 인해 **미완**.

### 2-2. mgpt env 의 torch 가 cpu-only

```
torch.__version__ = '2.12.0+cpu'
torch.cuda.is_available() = False
```

- wrapper smoke (4-frame) 는 CPU inference 였음 — 작동은 했지만 매우 느림.
- 공식 demo.py 는 CPU fallback 없어 직접 실행 불가.
- inference 1 sample 분 단위 (정확한 측정 안됨).

### 2-3. length=0 smoke 의 3시간 hang

- Process started 11:02:38, killed 14:06:42 (3시간 4분).
- CPU 누적 사용: 0.98 초.
- WorkingSet: 90 MB (model 로드 시작 안 함).
- Output: 0 lines.

→ patch 변경 부분 (`batch['length']` 단순 dict literal) 은 hang 원인 될 수 없음. 별개 외부 요인:
1. **conda activation lock**: 이전 wrapper smoke (`b50frw2qb` 직전 시도) 이 leak.
2. **HuggingFace 다운로드 시도**: 첫 model 로드 시 cached tokenizer / model 부재 → 다운로드 시도 + 네트워크 차단.
3. **subprocess stdin 대기**: conda run 의 prompt (yes/no 확인 등) 대기.

본 hang 의 정확한 원인 파악은 별도 진단 필요. **W-2026-001 의 length issue 와는 별개 sub-issue** 일 수 있음.

- 환경: 메인 `motion3d` (conda, python 3.10), MotionGPT inference `mgpt` (conda, python 3.10, torch 2.12.0+**cpu**).
- 명령어 (시도, 결과):
  ```
  # 1단계: 공식 demo.py 직접
  cd external_assets/MotionGPT
  conda run -n mgpt python demo.py --cfg ./configs/config_h3d_stage3.yaml \
      --example ./demos/t2m_mini.txt
  # → AssertionError: Torch not compiled with CUDA enabled (CUDA 미설치)

  # 2단계: length=0 patch 후 wrapper smoke

      --prompt "a person walks forward then sits down on the ground" \
      --n-frames 0 --seed 42
  # → 3시간 hang, manual kill
  ```
- 시드: seed=42.
- 산출물: hang 으로 output 없음. patch 는 rollback.
