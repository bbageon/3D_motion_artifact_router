> Date: 2026-05-30.
> Scope: Stage A+ 의 synthetic unsafe_as_safe 46.3% 가 단순 성능 부족 인지 **safety head 의 낙관 편향** 인지 진단. mining 전에 bias 원인 분리.

## 3. 7 진단 결과

### 3-1. Overall — PR-AUC + Confusion (unsafe=pos)

- **PR-AUC (unsafe=pos) = 0.825 ± 0.008** — P_safe 가 unsafe 탐지 시그널은 가짐 (random=base rate). 단 사용 방법 (threshold + argmax) 이 문제.
- Confusion @ P_safe≥0.5: TP=847 / FP=233 / **FN(unsafe-as-safe)=420** / TN=3549.
  - precision_unsafe=0.784 / **recall_unsafe=0.668** / F1=0.722.
  - **recall_unsafe 67% → P_safe 가 실제 unsafe 의 33% 를 놓침** (false-safe).

### 3-2. Per-tool unsafe_as_safe

| tool | unsafe_as_safe (pred-safe → 실제-unsafe) |
|---|---|
| BoneProjectionTool | **0.1%** ✓ |
| FootLockTool | **17.3%** ⚠️ |
| VelocitySmoothingTool | **17.8%** ⚠️ |

→ 편향이 **FootLock + VelocitySmoothing 에 집중**. BoneProj 는 거의 완벽 (작은 factor 효과, gate boundary 멀리).

### 3-3. Per-u unsafe_as_safe (boundary localization)

| u | unsafe_as_safe |
|---|---|
| 0.0 | 0.0% (identity) |
| **0.1** | **9.4%** |
| **0.2** | **23.9%** ⚠️ peak |
| 0.3 | 8.3% |
| 0.4–1.0 | 9–13% |

→ **편향이 unseen u=0.1–0.2 에서 집중** (coarse 학습 {0,0.5,1.0} 의 보간 실패 구간). u=0.2 가 23.9% 로 최악. Stage A 의 synthetic VelSmooth 비단조 violation (49% @ u=0.3 → 27% @ u=0.6 → 2% @ u=1.0) 영역과 일치.

### 3-4. Per-distribution label ratio + unsafe_as_safe

| distribution | train safe label rate | eval unsafe_as_safe |
|---|---|---|
| clean | 55.6% | 17.6% |
| near_boundary | 88.8% | 1.0% |
| g2_natural | 83.0% | 11.5% |
| synthetic_severe | 82.1% | 7.4% |

→ **class imbalance 가 표면적 원인 아님** (synthetic train safe label 82% 로 g2 와 유사). 그러나 **selected-vs-all (§3-5) 에서 synthetic 만 argmax bias 폭발**.

### 3-5. Selected vs all candidate — **A+ 46% 의 root cause**

argmax 가 위험 후보를 끌어올리는가? (top1 = predicted-safe argmax utility):

| distribution | all_cand unsafe | **top1 unsafe** | **lift** |
|---|---|---|---|
| clean | 57.6% | 0.0% | **−57.6%** (argmax 가 unsafe 회피) |
| near_boundary | 6.2% | 0.0% | −6.2% (회피) |
| g2_natural | 19.5% | 2.6% | −16.9% (회피) |
| **synthetic_severe** | **14.5%** | **33.3%** | **+18.8%** ⚠️ |

→ **synthetic 에서만 argmax 가 unsafe 후보를 +18.8% lift 로 끌어올림**. 이유: synthetic VelSmooth 의 unsafe 후보가 동시에 high utility (positive Q) → argmax 가 우선 선택. P_safe 가 이 high-utility-unsafe 영역 을 충분히 떨어뜨리지 못함 → argmax 통과. **이것이 Stage A+ 의 46% unsafe_as_safe 의 직접 mechanism**. CQL NeurIPS 2020 의 OOD action value overestimation 의 본 프로젝트 instance.

### 3-6. Calibration curve

[figure §a](figures/2026-05-30/psafe_bias_audit.png): predicted P_safe 0.55–0.85 영역 에서 actual safe rate 가 prediction 아래 (slight overconfidence). predicted 0.95+ 영역 은 well-calibrated (actual ≈ 0.93). 즉 **mid-confidence prediction 이 가장 unreliable**, high-confidence prediction 은 그나마 신뢰 가능.

### 3-7. Threshold sweep — conservative safety trade-off

| P_safe ≥ | syn unsafe_as_safe | syn act_rate | ovr unsafe_as_safe |
|---|---|---|---|
| 0.50 | 7.4% | 84.5% | 10.6% |
| 0.70 | 6.6% | 82.6% | 9.1% |
| 0.80 | 6.1% | 81.2% | 8.0% |
| 0.90 | 5.1% | 76.8% | 7.1% |
| 0.95 | 5.0% | 73.8% | 6.6% |
| 0.99 | 4.4% | 64.7% | 5.6% |

→ **conservative threshold 만으로는 부분 해결**: 0.5 → 0.99 로 syn unsafe_as_safe 7.4 → 4.4% (38% 감소). act_rate 도 85 → 65% 로 떨어짐. **A+ 의 46% 와의 격차 (38pp+)** 는 threshold 가 아니라 **argmax bias** (§3-5) 에서 옴.

## 4. 파악한 부분 — bias 의 root cause 분리

1. **bias 는 학습 자체보다 사용 방법 에 더 큰 비중**: P_safe head 의 PR-AUC 0.825 (괜찮음). 단 **argmax + leaky P_safe** 의 결합 이 synthetic 의 high-utility-unsafe 영역 을 끌어올림 (+18.8% lift, §3-5).
2. **편향 의 두 축 명확**: (a) **tool**: FootLock + VelSmooth (~17%); BoneProj 안전. (b) **u**: u=0.1-0.2 (9-24%) — coarse {0,0.5,1.0} 의 unseen 보간 영역. Stage B-1 hard-mining 의 우선 타깃 = **FootLock/VelSmooth × u∈[0.1, 0.3] × synthetic**.
3. **class imbalance 가 표면 원인 아님** — train safe label rate g2/syn/near 모두 80%+. 그러나 synthetic 의 **utility-safety joint distribution** 이 다름 (high-utility unsafe).
4. **conservative threshold 만으로는 불충분** (38% 감소 만). 진짜 해결 = **(a) Stage B-1 hard-mining + (b) Stage B-2 calibration + (c) real-gate 재검증 (필수, 옵션 아님)**.

## 5. Claim 변경 (사용자 directive 반영)

- ❌ "learned P_safe predicts safety reliably." — **invalid** (audit evidence).
- ✅ "Learned Q proposes candidate interventions; physical gate validation performs final safety filtering." — defensible.
- 구조 framing: **Q_utility = 좋은 후보 제안 / P_safe = 위험 예보관 (판사 아님) / real gate = 최종 실행 승인**.

→ docs/action_space_provenance.md §5-2-6 ("Q 높다고 바로 믿지 말 것") 의 **necessary** evidence 확보. 외부 공개 claim 도 위 구조로 작성 의무.

## 6. 다음 단계 (audit-driven 우선순위)

1. **Stage B-1 hard mining (audit-driven)**: 우선 mining 타깃 = **(FootLock OR VelocitySmoothing) × u∈{0.1, 0.15, 0.2, 0.25, 0.3} × synthetic_severe (특히 high-utility-unsafe 영역)**. 1차 unsafe_as_safe 0% → 33% 의 핵심 영역 보강.
2. **Stage B-2 conservative safety calibration**: isotonic / Platt 재캘리브레이션 + 보수적 threshold (≥0.9 또는 ≥0.95) + 별도 OOD detector (state 의 train support 내부인지 확인). 단 threshold 단독 한계 (§3-7) 인정.
3. **Stage 2 Q_safe 재학습**: A + A+ + B 합산 데이터 + two-head 재학습. P_safe 의 utility-safety joint 학습 강화 (예: triplet loss / contrastive 로 high-utility-unsafe 영역 분리).
4. **Closed-loop 평가**: real-gate 재검증 항상 ON 으로 평가 (사용자 framing — physical gate 가 final filter).
