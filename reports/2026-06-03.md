## 4. before-action observable 검증 (성공 조건 #2)

- **금지 feature 배제 확인**: `sample_id`·`trial_id`·`pool_dir`·`split`·`gate_result`·`quality_after`·`quality_gain`·`after_state`·`dense_oracle_action`·final standard metric 등 → schema 에 0건 leak (`forbidden_leaked=[]`).
- **after-action 휴리스틱 audit**: suspicious 0건. 단 `previous_accepted_gain`(history — 직전 step gain, 현재 action 전 관측) + `ensemble_gain_variance`(uncertainty — ensemble 예측 분산, 적용 후 결과 아님)는 `_gain` substring 으로 1차 flag 됐으나 **명세상 before-action observable** 이라 사유 박제 후 통과 (false positive).
- **실제 build (30 G2 motion)**: v0 dim assert 통과. **non-semantic NaN = 0** — motion(14)+artifact(7)+physical(7)+history(8) = 36 feature 전부 결정적 계산 + before-action observable 확인. semantic(4) 만 NaN (mgpt tm2t precompute 전, schema 위치 고정).

## 5. 미완 (다음 작업으로 명시, schema 는 고정)

## 6. 파악한 부분

1. **v0 의 36/40 feature 가 motion-router env 만으로 결정적·before-action observable** — schema 가 즉시 사용 가능 (semantic 4 만 cross-env).
2. **금지 feature 0 leak** — state/label 분리 (적용 전/후) 원칙이 schema 레벨에서 강제됨. q_proxy 정의 시 label(적용 후) 은 별도 관리.
3. v0/v1/v2 의 ablation 비교 가능성 (성공 조건 #4): builder 가 동일 motion 에서 결정적 vector 생성 확인. 같은 split/candidate/q_proxy 비교는 q_proxy 정의(다음 작업) 후.
4. target-aware claim 은 v1+ 에서만 (성공 조건 #5): v0 는 target 없이 build, v1 은 sample target 으로 build 확인.

## 10. AR-043 Dataset Predefined Issue Prevalence Audit

> Scope: AR-043 — AR-040(q_proxy/v0 ranker) 전에, 현재 학습·평가 데이터셋 안에 ArtifactRouter 가 사전에 정의한 artifact / physical issue 가 실제로 존재하는지 확인. **Claim Boundary: 정책 성능 증명 아님, dataset issue presence 전제 검증.**

### 산출물

- 도구: [tools/dataset_issue_prevalence_audit.py](../tools/dataset_issue_prevalence_audit.py)
- snapshot: [evals/snapshots/dataset_issue_prevalence_audit_v1.json](../evals/snapshots/dataset_issue_prevalence_audit_v1.json)

### 기준

| family | criterion |
|---|---|
| artifact proxy | evaluator score >= 각 evaluator 의 `SEV_LOW` |
| physical gate | evaluator score > clean calibration p99 |

artifact: FootFloating / BoneLength / VelocityJitter. physical: Penetrate / Float / Skate / JerkSpike / BoneLengthCV.

### 핵심 결과

| split | n | artifact_total mean | 핵심 issue |
|---|---:|---:|---|
| g2_full_pool | 600 | 0.0289 | BoneLength low+ 76.3%, FootFloating low+ 22.7% |
| g2_stress_holdout | 65 | 0.0775 | FootFloating low+ 80.0%, BoneLength low+ 90.8% |
| g2_natural_holdout | 99 | 0.0189 | BoneLength low+ 83.8%, FootFloating low+ 10.1% |
| clean_noharm_holdout | 100 | 0.0324 | FootFloating low+ 26.0%, VelocityJitter low+ 8.0% |
| synthetic_diag_holdout | 48 | 0.1683 | BoneLength/Jitter low+ 100%, Jerk/BoneCV gate>p99 100% |

정량 확인:

- g2_stress artifact_total mean = 0.0775.
- g2_natural artifact_total mean = 0.0189.
- stress/natural ratio = 4.10x.
- synthetic_diag 는 controlled diagnostic 으로 강한 issue 존재가 명확.

### 해석

1. **AR-040 전제는 성립**: g2_stress 와 synthetic_diag 에 사전 정의 issue 가 실제로 존재한다.
2. **g2_stress 는 실제로 artifact-rich**: g2_natural 대비 artifact_total 이 약 4.1배.
3. **단 clean_noharm 은 "artifact-free" 가 아님**: HumanML3D clean 에서도 FootFloating proxy 26%, VelocityJitter proxy 8% 가 잡힘. 따라서 clean_noharm 은 "GT라서 완전 깨끗함" 이 아니라 **보정으로 더 망치면 안 되는 reference/no-harm split** 으로 표현해야 함.
4. **BoneLengthCV 는 G2 전반에서 강한 signal**: G2 full/stress/natural 모두 BoneLengthCVEvaluator > clean p99 가 100%. 이는 generator skeleton consistency issue 또는 evaluator-threshold domain gap 가능성을 함께 의미한다.

### 정직 보고 / limitation

- Artifact evaluator 는 대부분 Category C proxy 이므로, 이 결과만으로 최종 motion quality claim 을 하지 않는다.
- physical p99 가 0 인 evaluator(Penetrate/Skate)는 `>p99` 가 "any positive" 와 같아짐. 본 snapshot 에서는 Penetrate/Skate 는 거의 0.
- G2 stress/natural 은 evaluator-defined split 이다. 사람 perceptual stress 와의 alignment 는 별도 검증 필요.

## 11. state/action feature namespace 충돌 제거 (사용자 directive)

사용자 지적: `target_type_encoding` 이 v1 state(local_target) 와 action 양쪽에 존재 → dict merge / vectorize 시 충돌 (입력 정의 모호성, 성능 문제 아님).

- 확인: state ∩ action 충돌 = `target_type_encoding` 1건 (정밀 확인).
- 수정: **action feature 전체에 `action_` prefix** (`action_target_type_encoding`/`action_target_side`/`action_u` 등). state block 이름은 spec 그대로 (블록 내 unique). 미래 충돌(`u`, `tool_*` 등)까지 방지.
- **충돌 감지 자가 검증 추가**: `verify_schema()` 가 `state_action_name_collisions` 계산 → `passed` 조건에 포함 (regression 차단). 현재 **collisions = [] , passed = True**. dim 불변 (v0 40/50, v1 64/74, v2 71/81).

### 11-1. 남는 불확실성 (사용자 지적, §3-22 `internal proxy assumption`)

v1 의 local evaluator / relation proxy 는 **internal proxy** — 실제 motion quality (FID/R-Prec/MM-Dist/perceptual) 와의 정렬은 **미검증**:

- `local_artifact_score` / `local_physical_score` / `parent_chain_bone_margin` / `contact_phase_consistency` 가 실제 quality 와 얼마나 맞는지는 **AR-040 이후 (q_proxy + standard metric 대조) 검증 의무**.
- 근거 (사용자 제공, 2020+ top-tier): semantic/naturalness state 후보 = HumanML3D CVPR 2022 / MoMask CVPR 2024 ; v1 relation/local physical = HuMoR ICCV 2021 / PhysDiff ICCV 2023 ; v2 support/uncertainty = CQL NeurIPS 2020 (offline OOD value overestimation).
- 표기: 본 proxy 들은 `internal proxy assumption` — learned policy 의 최종 quality claim 의 단독 근거 금지 (§3-20 Category C 일관).

→ AR-037 은 이제 v0/v1 실험을 시작할 수 있는 **재현 가능·namespace-clean state builder**. proxy-quality 정렬 검증은 다음 작업.
