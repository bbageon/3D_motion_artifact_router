## 2. 파악한 부분 — 주요 결과

### 2-1. 사용자 directive 의 분기점 정답 — **"B2 를 넘는 sequence 가 실제 존재"**

**Paired test (n=30 common, NetGain_A, B2 multi-compatible)**:

| Metric | Sequence Oracle (K=5) | B2 multi | Δ (oracle - B2) |
|---|---|---|---|
| NetGain median | **+0.314** | +0.180 | **+0.144** |
| NetGain mean | **+0.303** | +0.179 | +0.124 |
| n_strict_oracle / n_tie / n_loss | **30 / 0 / 0** (clean separation) | | |
| **Wilcoxon p (one-sided, oracle > B2)** | **9.3e-10** | | |
| **Cohen's d (paired)** | **+1.71** (very large) | | |
| Bootstrap CI median | [+0.100, +0.168] | | (no zero crossing) |
| Bootstrap CI mean | [+0.097, +0.148] | | (no zero crossing) |

→ **30/30 sample 모두 oracle strict > B2**. action space 의 천장 아님. **Multi-step RL 진입 정당한 motivation 확립**.

### 2-2. Search mechanism 의 정량 발견

- **best_length=5 dominant (16/30 = 53%)** — K=5 가 binding constraint. multi-artifact 의 본격 회복 에는 평균 5 step 필요.
- **first_action=FootLockTool 29/30 (97%)** — foot floating 이 multi-artifact 의 first priority.
- **Search complexity**: per sample ~2600 paths explored (range 1500-4500). Pruning (Score 비감소 + same-pair strength decay) 가 worst case 10^5 = 100K → ~수천 paths 로 축소.
- Same-pair strength decay 가 sequence 의 핵심: 큰 strength 로 시작 → 점차 감소 (예: FL/large → FL/medium → FL/small) → 정밀 회복. single-step 은 본 ramping 자체가 불가.

### 2-3. B7 framing 교정 박제

사용자 directive (2026-05-24) 인용:
> "B7 = contextual bandit baseline. B7 을 'RL' 이라고 단독 표현하지 않기. 'single-step RL-style policy' 또는 'contextual-bandit baseline' 으로 표기. 진짜 RL 은 trajectory-level value learning 이후부터 사용."

본 일지 (2026-05-25) 부터 정정 적용:
- **B7 = contextual-bandit baseline = single-step RL-style policy**. NOT trajectory-level RL.
- 본 프로젝트의 보고서 (2026-05-20, 2026-05-21 등) 는 이미 "B7 bandit" / "contextual bandit" 표기 일관 (grep 확인) — 본 directive 와 충돌 없음.
- "Multi-step RL" (부록 K-10, L-8 의 future work) = **Trajectory-level value learning** (Q-learning, value iteration, sequence-oracle imitation). 본 부록 M 의 +0.124 mean gap 이 정식 motivation.

## 3. 실험 메타 (재현)

### 명령

python -m tools.oracle_sequence_multi_run \
    --n-samples 30 --seed 42 --max-depth 5 \
    --task-id oracle_sequence_multi_v1 \

- conda env: `motion3d` (numpy 2.2.6, scipy 1.15.3, sklearn 1.7.2, torch 2.11.0+cu128).
- AGENTS.md §2-1 의 권장 env 명 `motion-router` 와 실제 사용 env `motion3d` 의 불일치는 별도 명시 (env mapping은 reproducibility-checklist 의 보조 항목).
- Synthetic multi-artifact recipe: `inject_foot_floating(lift_height=0.08, seed=42) → inject_jitter(noise_std=0.05, seed=1042)`.
- HumanML3D new_joints 의 sorted glob, np.random.default_rng(42).choice(len, 30) — B2 multi_v1 과 same split.

본 일지에는 시각화 미첨부 (sequence oracle 의 본질이 정량 분포 비교 — 다중 sample paired test). 본격 시각화는 multi-step RL 진입 후의 tool call trace + before/after motion GIF 단계.
