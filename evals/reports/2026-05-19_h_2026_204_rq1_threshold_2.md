#### 판정 해석

본 결과는 **rule_based.py 의 current prototype 의 한계** 노출:
- bone 에서는 oracle 수준 달성 (BoneProjectionTool 26/30 정확 매핑).
- **jitter 에서 BoneProjectionTool 잘못 매핑** (30/30) → 결정적 contradicts 원인.
- foot 에서는 FootLockTool 매핑 OK 이지만 strength / target_part / frame_range 가 부적절 (B2 와 거의 동일 NetGain).

원인 후보:
1. **`VelocityJitterEvaluator.recommendation` 의 잘못된 매핑** — evaluator 가 추천 tool 을 "velocity_smoothing_tool" 이 아닌 다른 값 반환.
2. **`DEFAULT_TOOL_LOOKUP` 의 mapping 누락** — `"velocity_smoothing_tool" → "VelocitySmoothingTool"` 매핑이 있긴 하지만, evaluator 가 다른 recommendation key 반환 시 lookup 실패 → 다른 tool 우연 선택.
3. **rule_based 의 priority sort 결함** — severity 가 같을 때 ordering 이 bone evaluator 를 먼저.

본 결과는 **사용자 framing 과 일관**: "system-level routing 의 가치는 oracle gap 의 일부만 close, perceptual rating 후속 필요".

#### HARKing 차단

본 결과로 임계 2 의 사전 등록 (median Δ ≥ +5%, p<0.05, d≥0.3) 을 relax 하지 않는다. 임계는 그대로, 결과는 contradicts 그대로. **rule_based.py 의 mapping bug 수정 후 재측정** 이 정공법.
