# W-2026-001 — MotionGPT (G2) length 제어 불가능 (degenerate 4-frame output)

## 발견 경위

[`reports/2026-05-19d.md §7-2`](../../reports/2026-05-19d.md) 의 Action 2 (G2 natural artifact 분포 측정) smoke test 에서 발견. 2 sample 모두 60+ 단어 detailed prompt 사용 + `n_frames=60` hint 에도 불구하고 `motion_001.npy`, `motion_002.npy` 모두 shape (4, 22, 3) 으로 degenerate 4-frame 출력.

## 정공법 시도와 실패

- **n_frames hint 변경**: `batch['length'] = [args.n_frames]` 로 60, 40, 100 시도. 모두 4 frames.
- **Prompt 변경**: 공식 [`external_assets/MotionGPT/demos/t2m.txt`](../../external_assets/MotionGPT/demos/t2m.txt) 의 detailed prompt 사용. 동일 결과.
- **Seed 변경**: seed 42, 43 모두 4 frames.

## 원인 분석

MotionGPT 의 `model.forward(batch, task='t2m')` flow:
1. `batch['length']` 를 capture 만 함 (length conditioning 미적용).
2. 실제 motion token 생성은 LM (T5) 의 `generate_direct(texts, do_sample=True)` 에 위임.
3. T5 의 default `max_new_tokens` (또는 stopping criteria) 가 짧은 token sequence 출력 → motion VQ-VAE detokenization 결과 매우 짧음 (4 frames).

본질적으로 **MotionGPT 의 length 제어 mechanism 자체가 batch['length'] 인자를 effective 하게 사용하지 않음** — generation 은 T5 LM 의 자율적 stopping 에 의존.

## Severity 근거 — **critical**

[H-2026-204](../hypotheses/H-2026-204.md) 의 `track_scope: [G1, G2]` 의 G2 측 검증이 본 issue 로 인해 **불가능**:
- G2 natural artifact 분포 측정 — Action 2 의 deliverable 수행 불가.
- G1 ↔ G2 bidirectional generator transfer ([H-2026-206](../hypotheses/H-2026-206.md)) 검증 — G2 측 데이터 부재로 불가.
- High-quality motion no-harm ([H-2026-203](../hypotheses/H-2026-203.md)) — G2 가 high-quality tier 가 아니라 G1 만 사용 가능하므로 일부 무관.

본 issue 는 **외부 공개 보류 조건** (AGENTS.md §3-14 critical 미해소).

## 해결 방향 후보

### 방안 A — MotionGPT 의 T5 LM generation 직접 호출 (코드 수정)

[`generators/_motiongpt_inference.py`](../../generators/_motiongpt_inference.py) 의 `model.forward(batch, task='t2m')` 호출을 분해해 T5 LM 의 `generate` 를 직접 호출. `min_new_tokens` 또는 `min_length` 인자로 강제. 작업량: 중 (MotionGPT 내부 코드 분석 필요).

### 방안 B — MotionGPT issue tracker 검색 + upstream fix 적용

[OpenMotionLab/MotionGPT issues](https://github.com/OpenMotionLab/MotionGPT/issues) 에서 length control 관련 issue 검색. 공식 fix 가 있으면 적용.

### 방안 C — Alternative G2 후보 generator

T2M-GPT (Zhang et al. CVPR 2023, MotionGPT 의 precursor) 또는 다른 token-based generator wrapping. G2 quality-tier 정의에 부합하면 active scope 유지 가능.

### 방안 D — Action 2 scope 재정의 (단기)

G2 inference blocker 가 해소되기 전까지 Action 2 는 **HumanML3D `new_joints` 의 test split** 을 G2 의 natural distribution proxy 로 일시 사용. 단 strictly G2 natural 이 아니므로 결과는 informational.

## 진단 시도 (2026-05-19, 사용자 directive)

사용자 4단계 진단 plan ([reports/2026-05-19e.md](../../reports/2026-05-19e.md) 인용) 진행 결과:

### 1단계 — 공식 demo.py 정상 길이 output 확인 (부분 막힘)

```
cd external_assets/MotionGPT
conda run -n mgpt python demo.py --cfg ./configs/config_h3d_stage3.yaml --example ./demos/t2m_mini.txt
```

결과: **CUDA 미설치 환경 이슈로 직접 비교 불가**.

```
AssertionError: Torch not compiled with CUDA enabled
  File "...\demo.py", line 166, in main
    model.to(device)
```

`mgpt` env 의 torch 가 **`2.12.0+cpu`** (CUDA 없음). 공식 demo.py 는 `cfg.ACCELERATOR == "gpu"` 분기로 무조건 `device = torch.device("cuda")` 호출 — CPU fallback 코드 없음. wrapper 의 [`_motiongpt_inference.py`](../../generators/_motiongpt_inference.py) 는 `if cfg.ACCELERATOR == "gpu" and torch.cuda.is_available()` 로 자체 CPU fallback 있어 동작은 했음 (단 4-frame degenerate output).

### 2단계 핵심 발견 — 공식 demo.py 의 batch['length'] = [0]

공식 demo.py 의 [`load_example_input`](../../external_assets/MotionGPT/demo.py) line 39:

```python
motion_lengths = [0] * len(Lines)
```

→ plain text prompt (`#` 없는 t2m.txt) 의 모든 sample 의 length 가 **0**. 즉 공식 정상 inference 는 `batch['length'] = [0]` 으로 호출.

wrapper 의 기존 `batch['length'] = [args.n_frames=60]` 은 공식 path 와 다른 호출 — 본 차이가 length issue 의 직접 원인 후보.

### 2단계 — length=0 patch 시도 (1차 hang, 2차 결정적 발견)

[`_motiongpt_inference.py`](../../generators/_motiongpt_inference.py) 의 `batch['length']` 를 `[0]` (n_frames=0 일 때) 으로 patch.

**1차 시도** (wrapper subprocess 경유):
```
conda run -n motion3d python -m generators.motiongpt_wrapper \
    --prompt "a person walks forward then sits down on the ground" \
    --n-frames 0 --seed 42
```
결과: **3시간 hang** (CPU 1초만 사용, output 0 lines). Manual stop. 원인 unclear — conda activation lock / subprocess buffering / 일시적 환경 이슈 추정.

**2차 시도** (wrapper subprocess 우회, `_motiongpt_inference.py` 직접 호출 + 절대경로 + `--no-capture-output`):
```
conda run -n mgpt --no-capture-output python <abs path>/generators/_motiongpt_inference.py \
    --motiongpt-root <abs>/external_assets/MotionGPT \
    --cfg configs/config_h3d_stage3.yaml \
    --ckpt <abs>/...motiongpt_s3_h3d.tar \
    --prompt "a person walks forward then sits down on the ground" \
    --n-frames 0 --seed 42 \
    --output <abs>/tmp_smoke/motion_length0.npy
```

**결과 (Runtime ~30초)**:
```
[INFO] batch['length']=[0], prompt[:60]='a person walks forward then sits down on the ground'
[OK] joints (4, 22, 3) (length_generated=4) -> .../motion_length0.npy
```

**결정적 발견**:
- length=0 (공식 demo.py 와 동일 path) 도 **4-frame degenerate output**.
- 이전 wrapper smoke (length=60) 와 동일 결과.
- **wrapper 의 batch['length'] 값을 어떻게 주든 결과 동일** → length issue 의 진짜 원인은 wrapper 의 length parameter 가 아니라 **MotionGPT 내부 T5 LM 의 generate 호출 자체**.
- 1차 hang 은 본 patch 와 무관한 일시적 외부 요인. 2차 시도가 정상 30초 완료.

**Patch rollback**: length=0 / length=60 결과 동일하므로 wrapper 의 batch_length 분기 의미 없음. 원래대로 [`_motiongpt_inference.py`](../../generators/_motiongpt_inference.py) `batch['length'] = [args.n_frames]` 원복.

### 3단계 — checkpoint/tokenizer/config 또는 T5 LM generate 동작 확인

2단계 결정적 발견 후 3단계 진입 방향:

**3a) T5 LM 의 generate parameter 강제** (가장 유력):
- MotionGPT 의 model 내부에서 T5 LM 이 `generate_direct(texts, do_sample=True)` 호출 시 default `max_new_tokens` / `min_new_tokens` 가 짧은 sequence stop 유도.
- `mGPT/models/mgpt.py` 또는 `mGPT/models/base.py` 에서 T5 generation parameters override 위치 식별 + min_new_tokens 강제.

**3b) Checkpoint 로드 시점의 vocab 확장 경고 영향**:
- transformers 메시지: "new embeddings will be initialized from multivariate normal distribution" — vocab 확장 (motion_id_512 등 추가 token) 시 LM head 가 재초기화 됐을 가능성.
- 단 checkpoint state_dict 로드 후 다시 그 부분이 trained weight 으로 덮어지므로 영향 미미할 것. 추가 확인 필요.

**3c) MotionGPT 의 motion VQ-VAE codebook 1-2 token short stopping**:
- LM 이 `<motion_id_codebook_size>` (start) → `<motion_id_codebook_size+1>` (end) 사이의 motion token 을 generate 해야 함. end token 이 너무 빨리 sample 되면 short motion 생성 (4 frames).
- 본 동작은 randomness + sampling temperature 의존. seed 변경 또는 sampling 옵션 (top_p, temperature) 조정으로 회피 가능.

**다음 진단 단계**: 3a (T5 generate parameter 강제) 가 가장 빠른 진단. `mGPT/` 코드 분석 + min_new_tokens injection 시도.
